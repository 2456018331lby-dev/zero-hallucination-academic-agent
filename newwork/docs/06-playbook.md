# 06 · 研究生科研场景 AI 指挥手册

> 面向：刚上研究生的人（通信 / 信息 / 电子方向）。
> 目标：把「调研、组会、写论文」这些高压场景，拆成**几句可以直接照着说的话**。
>
> 本手册里的每个场景都对应仓库里已经跑通的东西：
> - 流水线：`../skills/phd-literature-review/`（文献三件套）
> - 编排：`../scripts/orchestrate_mimo.py`（把体力活派给本机 MiMo）
> - 采集：`../scripts/litpool_fetch.py`（没 PDF 时先建池）
> - 平级能力：`.agents/skills/` 的 6 个 skill（引文审计 / 数学审查 / LaTeX 成稿 / 网页侦察）

---

## 零、先记住三条心法

1. **你只做判断题，AI 做叙述题和体力活。**
   选题、切入点、"这个方法到底行不行"——这些永远是你的。批量抽字段、逐文件遍历、
   格式化排版——这些一句规则就能说清的，全丢出去。
   判定标准：*这个子任务能不能写成不含歧义的「输入 → 输出」规则？* 能 → 派。
2. **一切数字必须能回到原文。**
   这是这套流水线唯一真正的护城河。AI 给你的任何一个百分比、dB 数、准确率，
   你都要能指着某篇 PDF 说"它写在这儿"。查不到就写「**文献未说明**」，不许它猜。
3. **指挥用三段式：目标 / 材料 / 产物，再补禁区与验收。**
   见下一节。缺了「材料在哪」和「不许做什么」，你 100% 会返工。

## 一、万能指挥句式（建议背下来）

```
【目标】我要在 <什么时候> 前，给 <导师 / 组会 / 审稿人> 交付 <什么东西>。
【材料】我的文件在 <绝对路径，例如 C:\Users\...\literature>。
【产物】要 <格式>，篇幅 <多少>，受众是 <谁>。
【禁区】不要编造任何题目 / 作者 / 期刊 / 实验数字；
        查不到就写「文献未说明」；不要自己换算或估算。
【验收】每条关键结论，请标出它来自哪篇文献的哪一处。
【步骤】先做 A，做完给我看，我确认后再做 B。
```

三句关键补充（很省事）：

- **锁格式**：`输出成一张表，列名照抄我给的模板，不要额外解释和寒暄。`
- **防过度加工**（派给 MiMo 时必写）：
  `本任务直接读文本即可完成，不要编写脚本、不要调用 PowerShell 或外部命令来间接统计。`
- **要留痕**：`把原始证据和你做了什么写进 work/ 目录，我要能复现。`

## 二、五个高频场景

### 场景 1 · 组会文献汇报（每 1–2 周一次，最高频）

> 压力来源：*"这周又没读论文，明天要讲。"*

**你要说的话（直接复制，改路径）**

```
帮我做这周的组会文献汇报。
文献在 C:\Users\24560\Desktop\study\pidemo\newwork\examples\otfs-isac\input\literature
主题是「高机动低空场景下的 OTFS 通感一体化」。
要三样东西：①文献阅读对比表格（Markdown + Excel）②方向调研报告 ③15 页组会 PPT。
受众是导师和同方向研究生，请用科研口吻，不要科普腔。
规则：所有字段必须来自 PDF 原文，缺的写「文献未说明」，绝不编造。
PPT 要学术风，每页点一次就讲完（动画做成级联）。
做完把接地门禁跑一遍，告诉我通过率。
```

**AI 实际会走的链**

```
extract_pdfs.py（双栏清洗抽取全文）
  → 精读并按 15 字段抽表（problem/method/innovation/setup/results/
     pros/cons/relation/recommend/why）
  → literature_table.json（唯一数据源）
  → build_table.py 渲染 MD + XLSX
  → verify_grounding.py 接地门禁（硬关卡）
  → 7 节调研报告
  → slidep 出 15 页 .pptx + retime_animations.py 加入场动画
```

**你会拿到**：`文献阅读对比表格.md/.xlsx`、`方向调研报告.md`、`XX方向汇报.pptx`（讲义版）
+ 门禁报告。

**你必须自己判断的 3 件事**

1. **精读名单**：它挑了 8–12 篇，剩下的淘汰理由站不站得住？（名单是它给你的，取舍是你的）
2. **cons 那一列**：每篇的"局限"是否真的成立、是否说到了痛处——这是你讲组会时最能体现水平的地方。
3. **recommend 档位**：哪些"推荐重点讲"、哪些"仅作背景"，直接决定你 15 分钟的讲述结构。

**省下的时间**：手工读 12 篇 PDF + 做表 + 写报告 + 排版 PPT，通常 2–3 个工作日 → **半天内**。

### 场景 2 · 开题 / 方向调研（决定未来两年做什么）

> 压力来源：*"导师让我找方向，我连关键词都拿不准。"*

**第一步：先建一个文献池（你还没有 PDF 时）**

```
我要调研「<方向关键词>」这个方向。我现在没有文献，你帮我建一个文献池：
从开放获取的论文里找，只要 2022 年以后的，优先顶刊顶会，先给我一份候选清单
（含标题/年份/来源/是否开放获取），我看过再决定下载哪些。
注意：下载下来的每篇都要核对标题和正文是不是同一篇。
```

> 底层就是 `../scripts/litpool_fetch.py`。它会写一份 `manifest.json` 记录每条的
> query / host / DOI / 排除原因——**来源可审计**，这比"AI 找的"值钱得多。
> 两个已记录的坑：HAL 的全文下载被机器人门挡住（只能当发现源）；
> 有些库下到的 PDF 正文与标题不符（实例二里抓到过 1 篇），必须抽查。

**第二步：出调研报告并提出切入点**

```
基于这个文献池，给我一份 7 节的方向调研报告，重点回答三件事：
1）这个方向的发展脉络分几个阶段、每阶段的代表方法是什么；
2）现在已经解决 vs 还没解决 的问题各有哪几条；
3）从"没解决"里，给 3–5 个适合硕士/博士开题的切入点，并说明每个的可行性和代价。
每个论点都要标出依据哪几篇文献。不确定的地方明说，不要圆场。
```

**你会拿到**：背景调研 + 已有工作对比 + **"5 个挑战 → 5 个切入点"** 的把式
（这正是导师在开题时最想听到的结构）。

**你必须自己判断的**：切入点是不是真新、你的实验室有没有对应的设备和数据、能不能在学制内做完。
**这三条 AI 永远不知道答案。**

### 场景 3 · 写论文（学位论文 / 小论文）

> 压力来源：*"框架搭不起来、格式老被挑、引文怕错。"*

**分三步下指令，别一次全交出去。**

**(a) 先定大纲和符号表**

```
我要写一篇关于「<题目>」的学位论文（硕士/博士），
框架请按国内规范（GB/T 7713.1）来。
先给我：章节目录（到三级标题）+ 一份符号表（每个符号的含义、量纲、首次出现位置）。
我确认后再动笔写正文。
```

**(b) 再写正文（半成品也允许）**

```
按这个大纲写第 1、2 章。第 2 章要包含相关工作的对比三线表。
实验还没做，涉及实验数据的部分留可编译的占位符，不要编造数字。
语言要像我写的，不要 AI 味（不要"众所周知""具有重要意义"这类套话）。
参考文献按 GB/T 7714 著录。
```

**(c) 交稿前跑两道门禁（这一步千万别省）**

```
投稿/送审前，帮我做三件事：
1）把参考文献全部核对一遍：每条都要用 DOI 去官方元数据比对
   作者、标题、年份、卷期页码，对不上的直接标出来；
2）检查全文符号一致性、定理陈述与证明强度是否匹配、
   算法假设之间有没有冲突；
3）把 AI 味的套话清理一遍。
先给我问题清单，我确认后再改文件。
```

> 底层分别是 `citation-auditor`（**P0 硬门禁**：作者/卷期页错配一律 FAIL）、
> `math-reviewer`（符号契约 + 定理强度 + 假设冲突）、`thesis-latex-writer`（GB/T 合规 + 反 AIGC）。
> 引文审计的第一条铁律是：**禁止模型凭记忆写 author 字段**，一律以 Crossref/OpenAlex 回填为准。
> 这条能救你——本科/硕士论文最常见的致命错误就是作者张冠李戴。

**你会拿到**：可编译的 LaTeX 工程（`main.tex` + `references.bib` + `main.pdf`）+ Word 导出
+ 两份门禁问题清单。

**你必须自己做的**：创新点、理论推导的核心思路、实验设计——**这些是论文的命，不能外包**。
AI 只能帮你把它写清楚、排版、查错。

## 四、必须由你兜住的 6 个环节（AI 替不了）

| # | 环节 | 为什么 |
| :-- | :-- | :-- |
| 1 | **选题与切入点的最终决定** | AI 不知道你实验室有什么、导师偏好什么、你剩几年 |
| 2 | **下载条目与正文的一致性抽查** | 采集脚本只保证 URL 可达，不保证内容对得上（实例二抓到过） |
| 3 | **精读名单的取舍** | 它给候选和理由，拍板是你 |
| 4 | **每条关键数字回原文核对** | 这是"零幻觉"的最后一道人肉关卡 |
| 5 | **论文的创新点与理论主线** | 外包了你就没论文了 |
| 6 | **提交前的通读** | 门禁能查错，查不出"这不像我写的" |

## 五、红线（学术诚信，违反代价极高）

1. **不许 AI 编造任何文献、数据、实验结果。** 这是本套工作流所有门禁存在的理由。
   AI 产出的任何数字，你若无法在原文找到，就**不许进入交付物**。
2. **参考文献的 author 字段禁止由模型"想"出来。** 必须走 DOI → 官方元数据回填。
3. **AI 是辅助工具，不是作者。** 论文的核心贡献、推导思路必须是你自己的。
   写完后你应当能对每一段负责，并遵守学校/期刊的 AI 使用披露规定。
4. **不要跳过门禁。** 门禁报 FAIL 就回原文改，不要"放宽门禁让它过"。
   （实例二里 34 号文献的 DOI 只在开放登记库里、正文没印 → 正确处置是**改记到附录**，不是放宽门禁。）
5. **数据不许美化。** 不显著就写不显著。

## 六、一次真实指挥长什么样

> 你：*帮我做 OTFS-ISAC 方向的组会 PPT，文献在 `<路径>`，五天内要讲。* （详见 `../examples/otfs-isac/`）
>
> AI 的回话应该长这样：
>
> 1. 确认文献池里有 39 篇 → 清单给我看，我圈定 12 篇精读；
> 2. 抽取全文 → 抽 15 字段 → 出表（**同时**把 12 篇的元数据抽取派给 MiMo 并行做校对）；
> 3. 门禁：12/12 通过，但我自己会抽查 3 条数字；
> 4. MiMo 回执回收 → 逐条比对，抓出 `[39]` 作者张冠李戴、`[30]` 整篇漏在表外 → 修正；
> 5. 出报告 + 15 页 PPT + 动画；
> 6. 交给我：表 / 报告 / PPT / 门禁报告 / 差异记录。
>
> **注意第 2 和第 4 步**：AI 一边派 MiMo 去做机械核对，一边自己干重活；
> 但**每一项结论都回到原文核过**——这就是"你指挥 AI"而不是"AI 替你干活"。
