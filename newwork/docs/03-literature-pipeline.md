# 03 · 文献调研三件套流水线规范

> 输入：一批**本地 PDF**。输出：① 15 字段文献阅读对比表 ② 7 节方向调研报告 ③ 15 页学术风组会 PPT。
> 全套规范同时固化在 skill `skills/phd-literature-review/SKILL.md` 里，本文件是它的说明性版本。

## 零、六条不可违反的纪律

1. **只用本地证据**。所有内容来自用户提供的 PDF；不得从记忆、网络或其他语料导入事实。
2. **不编造**。题目、作者、期刊、arXiv 编号、数据集名、参数、实验数字一律不得臆造；不确定就回原文查。
3. **缺口显式化**。缺字段写「**文献未说明**」。
4. **先浏览再精读**。论文多时先全部过一遍，再挑最相关的 **8–12 篇**精读，并说明淘汰了哪些及原因。
5. **科研分析口吻**，不做科普。受众＝导师＋同方向研究生。
6. **不要相信仓库里现成的对比表**。历史文件常有错（编号张冠李戴、数字被替代），必须从 PDF 重建。

## 一、流程（按序执行）

```
① 清点全部 PDF → ② 筛选 8–12 篇 → ③ 精读并抽取 15 字段
   → ④ 落盘 literature_table.json → ⑤ 渲染 MD + XLSX
   → ⑥ 写 7 节调研报告 → ⑦ 建 15 页 PPT
```

| 步 | 命令 / 动作 | 产物 |
| :-- | :-- | :-- |
| ① | `extract_pdfs.py --src <PDF_DIR> --out <WORK>/pdftext --libs <LIBS>` | 每篇一个 `.txt`（含 `<<<PAGE n>>>` 分隔）+ 首页摘要打印 |
| ② | 人工/主代理判断 | 入选清单 + 淘汰清单及理由 |
| ③ | 逐篇精读，抽 15 字段 | 证据草稿（字段 → 原文引用/页码） |
| ④ | 写 `literature_table.json` | 唯一数据源（含 `meta` + `papers`） |
| ⑤ | `build_table.py --json <json> --out-dir <DIR> --libs <LIBS>` | `文献阅读对比表格.md` + `.xlsx` |
| ⑥ | 撰文 | `方向调研报告.md`（7 节） |
| ⑦ | 见 `skills/phd-literature-review/references/ppt-storyboard.md` | `STORY.md` + 15 页 pptx |

**核对纪律**：③ 阶段抽出的每个 arXiv 编号、数据集名与数字，都要回 `.txt` 里字符串检索确认一遍。

## 二、15 字段定义（JSON 键名固定，勿改）

| 键 | 中文列 | 内容 |
| :-- | :-- | :-- |
| `id` | 序号 | `[1]`、`[2]`…（这个标签在报告与 PPT 里复用） |
| `title` | 论文题目 | 原文标题 |
| `authors` | 作者 | 第一作者 et al. 或全列 |
| `year` | 年份 | 发表年 |
| `venue` | 会议/期刊 | 期刊/会议；若是预印本写「arXiv 预印本（arXiv:xxxx.xxxxx）」 |
| `problem` | 研究问题 | 该文攻的具体问题 |
| `method` | 核心方法 | 机理（波形 / 架构 / 算法） |
| `innovation` | 主要创新点 | 真正新在哪 |
| `setup` | 数据集/实验设置 | 数据集、场景、关键参数、基线 |
| `results` | 关键实验结果 | **原文给出的**数字 + 对应指标 |
| `pros` | 方法优点 | 优势 |
| `cons` | 方法局限 | 代价与限制，直说 |
| `relation` | 与本研究方向的关系 | 在该方向脉络中的位置 |
| `recommend` | 是否建议重点汇报 | 推荐 / 可选 / 仅作背景 |
| `why` | 推荐汇报理由 | 一句话 |

`meta` 块需含：`direction`、`subtitle`、`source_note`、`rules`、`generated`（可选 `notes[]`）。

## 三、7 节调研报告

1. **概述** —— 一段话说清：为什么重要、边界在哪、核心张力是什么。
2. **发展脉络** —— 3–5 个阶段，每阶段点名定义它的文献。
3. **方法分类** —— 3–5 个互斥族；每族给：思路、代表文献、代价。
4. **代表性文献** —— 5–8 篇，逐篇**批判性拆解**（不是摘要）。
5. **对比总结** —— 「已解决 / 未解决」二分（如 *5 项已解决 vs 7 项未解决*）。
6. **挑战与未来方向** —— 每个挑战 → **可落地的博士生切入点**（带 推荐高/中 标记）。这是导师最看重的部分。
7. **总结** —— 一段话收束核心研究逻辑，落在关键命题上。

## 四、PPT 规范（15 页）

三幕结构：**为什么难 → 别人怎么做 → 还缺什么**。
配色为学术蓝白（宝蓝 `#1E4FA8`、页面 1280×720）。
逐页分镜、色板 token、`slidep` 命令与**高度预算**全部见
`skills/phd-literature-review/references/ppt-storyboard.md`。

**铁律**：第 09–11 页上出现的每个 KPI 数字，都必须能在对比表里找到**同一个值**；
PDF 里没有的数字，不许上页。

## 五、易踩的坑

- `slidep-validate` / `slidep upsert-dsl` 的 `--project` 必须传**绝对、正斜杠**路径，否则会报出假的 `C:\c\Users\...`。
- 页面**垂直预算** = 720：标题栏页的内容区是 580；算错会静默溢出。
- 重新排序页面后，页脚页码要同步改。
- 「看起来很有用」的现成 digest / 对比表若与 PDF 对不上，**以 PDF 为准**，删掉重做。
- `libs/site-packages` 用 `pip install --target` 隔离安装；不要用全局 pip。
