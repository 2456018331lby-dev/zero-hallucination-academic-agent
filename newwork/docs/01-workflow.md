# 01 · 主从协作工作流（把子任务派给 MiMo）

## 一、模式

```
                 ┌──────────────────────────────────────────┐
                 │  主代理（orchestrator / 你 / WorkBuddy）   │
                 │  · 目标定义   · 任务分解   · 全部判断       │
                 │  · 证据核对   · 最终交付物                  │
                 └───────────────┬──────────────────────────┘
                                 │  ① 写一份自包含 brief
                                 │  ② orchestrate_mimo.py 派发
                                 ▼
                 ┌──────────────────────────────────────────┐
                 │  MiMo Desktop（subagent，本机）           │
                 │  · 只做规则明确的重复性劳动                │
                 │  · 只读/遍历/抽取/格式化                   │
                 └───────────────┬──────────────────────────┘
                                 │  ③ 直到 idle
                                 ▼
                 ④ 主代理回收结果 → ⑤ 交叉核对 → ⑥ 采信或打回
```

**核心原则**：主代理 **不做** 可以用一段无歧义规则描述的重复劳动（那会烧掉宝贵的
上下文预算）；MiMo **不做** 需要判断力的事。

---

## 二、哪些任务适合派给 MiMo

| ✅ 适合（规则明确、可穷举、无需判断） | ❌ 不适合（需要判断/责任） |
| :-- | :-- |
| 批量从 N 个文件抽取固定字段 | 决定选题、决定切入点 |
| 逐文件统计 / 计数 / 格式规整 | 评价某方法"好不好" |
| 按给定模板重排、改写成表格 | 撰写最终结论与推荐意见 |
| 检索并汇总某类资料（清单化） | 决定哪些内容进入交付物 |
| 交叉检查 A 与 B 是否一致 | 处理歧义与冲突 |

**判定口令**：*能否写成不含歧义的「输入 → 输出」规则？* 能则派；不能则留。

---

## 三、派发的五条铁律

1. **自包含**。MiMo **看不到**主代理的对话。所有输入路径、字段定义、输出格式、验收标准都要写进 brief。
2. **绝对路径**。用 Windows 绝对路径（`C:\...`），不要让它猜相对路径。
3. **输出格式锁死**。给出**表头模板**或示例行，并规定"不要额外解释、寒暄或前言"。否则你会拿到一段需要再清洗的自然语言。
4. **明确禁止项**。写清"只读"、"不要写文件"、"不要联网"、"看不到就写「未找到」，不要推测"。防止它自作主张产生副作用。
5. **防止过度加工**（实测教训）。MiMo 有强烈的"工程化"倾向：一个"读文本抽字段"的任务，
   它会自己升级成"写脚本统计页码 + 调 PowerShell + 全文回搜"。
   在 brief 里明确写一句：
   > *本任务只需直接读取文本内容即可完成，不要编写脚本、不要调用 PowerShell/外部命令来间接统计。*
   可显著压缩 turn 数与时延。

> brief 模板见 `examples/bupt-isac/briefs/mimo-metadata-audit.md`。

## 四、延迟与心跳（重要：它"看起来卡住"是正常的）

**MiMo 单轮 agentic 任务很慢，且事件之间会有数分钟空档。这不是死锁。**

实测数据（本实例，11 个文本文件、纯字段抽取）：

| 观测 | 值 |
| :-- | :-- |
| 总耗时 | **≈15 分钟**（桥接脚本 900s 超时先到，但 MiMo 内部已把任务标记 `done`，回执完整） |
| 最长静默空档 | **≈9 分钟**（`16:48:56 → 16:57:38`，期间无任何事件输出） |
| 内部工具调用 | 6 个 assistant turn，含 powershell / python 调用 |

因此：

- **默认 `--timeout` 设为 1800s**，真实任务可再调大。
- **`--heartbeat`（默认 60s）** 会周期性往 stderr 打印 `[heartbeat] alive Ns / Ms`。
  看到它就在动，说明**活着，只是慢**；长时间连心跳都没有才是真卡。
- 脚本现在返回**结束原因**：`idle`（正常完成）/ `timeout`（被截断，回执可能不全）/ `closed` / `error`。
  超时**不等于**失败 —— 先直接读一次会话历史，MiMo 很可能已经答完了：

```bash
$PY "NW/skills/mimo-desktop-bridge/mimo_bridge.py" messages <sid> --max-chars 4000
```

> 实现注意：`watch()` 用**后台线程读流 + 主线程发心跳**。
> 不要试图给 `readline()` 加 socket 超时做心跳 —— `http.client` 的 chunked reader
> 一旦超时就永久损坏，之后每次读都抛 `OSError: cannot read from timed out object`。

## 五、操作步骤

```bash
# 1) 确认 MiMo 在跑，且目标会话处于「完全访问权限」（否则工具调用会阻塞）
$PY "NW/skills/mimo-desktop-bridge/mimo_bridge.py" health
$PY "NW/skills/mimo-desktop-bridge/mimo_bridge.py" sessions

# 2) 写 brief（自包含 + 绝对路径 + 锁死格式 + 明确禁止项）

# 3) 派发并等待完成，结果自动落到 --out
$PY "NW/scripts/orchestrate_mimo.py" \
    --brief-file "<brief.md>" \
    --out "<result.md>" \
    --workspace "C:/Users/24560/Desktop/study/pidemo" \
    --timeout 1800 --heartbeat 60

# 4) 若只想看/不等待：
#    --quiet 关闭事件流回显；--heartbeat 0 关闭心跳；--session ses_xxx 显式指定会话
```

脚本内部做五件事：按 `--workspace` 匹配 MiMo 会话 → `POST /turns` → 后台线程订阅 SSE
→ 主线程发心跳直到 `idle`/`timeout` → 取**最后一条 assistant 消息**写入 `--out`。

## 六、回收后必须做的事：交叉核对

**把 MiMo 的产出当作"待验证的草稿"，不是结论。**

1. **抽样式核验**：随机挑 2–3 行，回到原始文件里检索，确认无误。
2. **与主代理自己的产物对比**：本次实例中，MiMo 的元数据表与主代理的 `literature_table.json`
   做了逐条比对（见 `examples/bupt-isac/work/`）。
3. **记录差异**：一致 → 采信；不一致 → 以原文为准，并修正。
4. **留痕**：把 MiMo 原始回执和核对结论都写进 `work/`，方便复现与追责。

> 原则：*trust but verify*。子代理的总结描述的是它**打算**做什么，不一定是它**实际**做了什么。

---

## 七、反模式（别这么干）

- ❌ 把"帮我调研一下这个方向"直接丢给 MiMo —— 无输出格式、需判断，必然返工。
- ❌ 让 MiMo 写最终交付物 —— 交付物的正确性由主代理负责。
- ❌ 只给相对路径或"就是那个文件夹" —— MiMo 的会话工作目录未必和你一样。
- ❌ 不核对直接采信 —— 子代理会偶发"自信的错误"。
- ❌ 在权限未确认时派发 —— 会卡到 timeout，浪费时间和额度。
- ❌ **看到没输出就以为卡死并掐掉** —— 先看心跳；MiMo 有长达 9 分钟的正常静默期。

## 八、本实例的一次真实派发

| 项 | 内容 |
| :-- | :-- |
| 子任务 | 从 11 个全文 txt 中抽取「文件名 / arXiv 编号 / 年份 / 标题 / 页数」 |
| 为什么派 | 纯规则抽取、重复 11 次、无需任何判断 |
| brief | `examples/bupt-isac/briefs/mimo-metadata-audit.md` |
| 回执 | `examples/bupt-isac/work/mimo_metadata_audit.md`（11 行，格式完全合规） |
| 耗时 | ≈15 分钟（含一次 9 分钟静默）；桥接 900s 超时先到，但回执完整 |
| 核对 | `examples/bupt-isac/work/verify_mimo_audit.py` → `mimo_audit_verification.md` |
| **结论** | **44 / 44 项完全一致，0 不一致 → 采信** |

> 一次真实的正例：MiMo 自报了 `共 11 个文件，其中 arXiv 编号缺失 0 个`，与主代理独立数据吻合。
> 但仍必须核验 —— 这是流程，不是对它的不信任。
